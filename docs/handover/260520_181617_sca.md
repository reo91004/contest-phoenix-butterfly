## 결론

현재 RTL은 **기능적 정합성은 꽤 잘 맞아 보이지만**, 지금까지의 TVLA 실패는 “OpenTitan식 datapath blanking을 더 많이 넣으면 해결될 문제”라기보다 **active-cycle arithmetic leakage가 남은 문제**로 보는 게 맞습니다. 특히 Stage 4b가 현재 최선이지만, `mldsa_intt ≈ 113–115`, `mlkem_pwm ≈ 104–105`, `mldsa_pwm ≈ 75–78` 수준이라 4.5 기준 근처의 통계적 잡음이 아니라 명백한 누출입니다. Goodwill식 TVLA는 동일 시점에서 독립 데이터셋이 ±4.5를 넘는지를 실패 신호로 보는데, 현재 값은 그보다 훨씬 큽니다. 또한 긴 trace에서 4.5 임계값 해석은 보수적으로 다뤄야 한다는 지적도 있지만, 지금처럼 수십~백 단위 t-value인 경우에는 임계값 논쟁으로 설명되지 않습니다. ([NIST CSRC][1])

내가 보는 핵심 원인은 세 가지입니다.

1. **unused path blanking이 아직 완전하지 않다.** 특히 pointwise/PWM read path와 ML-DSA PWM의 unused `a` delay path가 의심됩니다.
2. **COMP3 내부에서 ML-KEM multiplier cone과 ML-DSA multiplier cone이 동시에 토글됩니다.** 이건 OpenTitan blanking 원칙과 정면으로 안 맞습니다.
3. 그걸 고쳐도 **선택된 active modular multiplication/reduction 자체는 계속 secret-dependent switching을 합니다.** 따라서 최종적으로는 shuffling 또는 partial/full masking 없이는 “완전한 TVLA pass”를 기대하기 어렵습니다.

OpenTitan OTBN의 blanking 설명을 보면, 사용하지 않는 path는 0으로 강제하고, blanking control은 glitch를 피하기 위해 flop에서 직접 나오도록 하며, bignum ALU/MAC 내부의 불필요한 datapath까지 blanking한다고 되어 있습니다. 즉 “invalid cycle 청소”만으로는 부족하고, **현재 instruction에서 functionally unused인 read/write/arithmetic cone을 실제로 끊어야** 합니다. ([OpenTitan][2])

기준은 대체로 맞습니다.

| ------ | ---------------------------------------------------------------------------------------: | -------------------------------------------------------------------------------------------------- |

## 2. 지금까지의 TVLA 결과 해석

현재 문서 기준으로 Stage 4b가 가장 좋은 후보입니다.

| Operation    | Baseline max |t| | Stage 4b max |t| | 해석          |
| ------------ | ---------------: | ---------------: | ----------- |
| `mlkem_ntt`  |           84.901 |           96.516 | 오히려 악화      |
| `mlkem_intt` |           65.052 |           42.888 | 크게 개선       |
| `mlkem_pwm`  |          114.713 |          103.869 | 개선됐지만 여전히 큼 |
| `mldsa_ntt`  |          132.180 |           85.738 | 크게 개선       |
| `mldsa_intt` |          135.012 |          112.877 | 현재 worst    |
| `mldsa_pwm`  |          144.055 |           78.170 | 크게 개선       |

Stage 4b의 핵심 의미는 이겁니다.

* invalid-cycle PRD flushing은 ML-DSA 계열에 실제 효과가 있었습니다.
* COMP blanking은 active window에도 영향을 줬습니다.
* 하지만 남은 peak는 여전히 active arithmetic window에 있습니다.
* `mlkem_pwm` peak가 baseline, Stage 2, Stage 3d에서 같은 위치 63에 남았다는 문서 기록은 특히 중요합니다. 이건 “이전 값 잔류”라기보다 해당 PWM cycle의 실제 연산 또는 read/write datapath 누출입니다.
* Stage 3e에서 PRD를 끄자 ML-DSA PWM/NTT 개선이 사라진 것도 PRD가 residual-state 누출에는 효과가 있었음을 보여줍니다. 반대로 `mlkem_pwm`이 거의 안 움직인 것은 그쪽이 invalid-cycle 문제가 아니라 active datapath 문제라는 뜻입니다.

OpenTitan AES 문서의 PRD clearing도 비슷한 성격입니다. register와 multiplier 내부 상태를 pseudo-random data로 덮고 multiplier를 돌려 내부 상태와 correction term을 지우는 접근이지, active secret computation을 masking하는 기법 자체는 아닙니다. ([OpenTitan][5])

FIPS 204도 ML-DSA 구현에서 민감한 intermediate data를 더 이상 필요 없으면 파기하라고 요구하지만, 그것이 active arithmetic leakage를 제거한다는 뜻은 아닙니다. ([NIST Technical Series][4])

## 3. 구현상 가장 의심되는 누출점 / 버그 후보

### A. `comp3_agile_modmul.v`: ML-KEM cone과 ML-DSA cone이 동시에 계산됨

현재 `rtl/comp/comp3_agile_modmul.v:18-51` 구조는 다음과 같습니다.

```verilog
array_schoolbook_agile16 u_kem_lo_mul (... a_i[15:0],  b_i[15:0]  ...);
array_schoolbook_agile16 u_kem_hi_mul (... a_i[31:16], b_i[31:16] ...);

mldsa_karatsuba24 u_dsa_mul (
    .a_i(a_i[23:0]),
    .b_i(b_i[23:0]),
    .p_o(dsa_raw48)
);

assign c_o = opmode_i ? dsa_out : kem_out;
```

즉 output mux만 `opmode_i`로 고르고, **두 multiplier/reducer cone은 항상 secret operand를 보고 토글**됩니다.

이건 기능적으로는 맞지만 SCA 관점에서는 매우 큰 문제입니다.

* ML-DSA mode에서도 ML-KEM 16-bit lane multiplier들이 ML-DSA operand의 low/high slice를 보고 토글합니다.
* ML-KEM mode에서도 ML-DSA Karatsuba/Montgomery cone이 packed operand의 24-bit slice를 보고 토글합니다.
* OpenTitan식 blanking 철학은 “현재 instruction에 필요 없는 ALU/MAC path를 blanking”하는 것이므로, 이 구조는 아직 blanking이 미완성인 상태입니다. ([OpenTitan][2])

우선순위 1번 패치입니다.

```verilog
wire use_dsa = opmode_i;  // 가능하면 flopped/predecoded control에서 온 값 유지

wire [31:0] kem_a = use_dsa ? 32'b0 : a_i;
wire [31:0] kem_b = use_dsa ? 32'b0 : b_i;

wire [23:0] dsa_a = use_dsa ? a_i[23:0] : 24'b0;
wire [23:0] dsa_b = use_dsa ? b_i[23:0] : 24'b0;
```

그다음 KEM multiplier는 `kem_a/kem_b`, DSA multiplier는 `dsa_a/dsa_b`만 보게 해야 합니다. 이 패치는 기능 변화가 없어야 하고, TVLA 관점에서는 “unused algorithm cone leakage”를 분리해서 볼 수 있는 가장 좋은 실험입니다.

### B. `phoenix_top.v`: pointwise/PWM read enable이 모든 bank를 켬

현재 `rtl/phoenix/phoenix_top.v:326-331`입니다.

```verilog
wire       core_reads_both_sides = is_mlkem_pwm || is_mldsa_pwm;
wire [3:0] core_mu_read_en = (idx_valid && (!ctl_mem_down || core_reads_both_sides)) ? 4'hf : 4'b0;
wire [3:0] core_md_read_en = (idx_valid && ( ctl_mem_down || core_reads_both_sides)) ? 4'hf : 4'b0;
```

문제는 `4'hf`입니다.

`read_addr`는 `pack_addr4(...)`로 만들어지는데, pointwise/PWM에서는 실제 사용하는 bank가 1개 또는 2개뿐입니다. 사용하지 않는 bank의 address는 기본 0이 됩니다. 그런데 `poly_memory_updown.v:117-119`는 `a_en=1`이면 `mem[a_addr]`를 output register에 냅니다.

```verilog
a_dout <= a_en ? mem[a_addr] : {DATA_W{1'b0}};
```

따라서 pointwise/PWM에서 사용하지 않는 bank도 `mem[0]`을 계속 읽을 가능성이 있습니다. 즉 **unused BRAM read path가 secret memory value를 출력하고 토글**합니다. 이건 OpenTitan이 말하는 register-file read path blanking과 정확히 같은 종류의 누출점입니다. ([OpenTitan][2])

우선순위 2번 패치입니다.

```verilog
wire [3:0] read_mask_fft =
    pack_we4(idx_valid, bk0a, bk0b, bk1a, bk1b);

wire [3:0] read_mask_mlkem_pwm =
    pack_we1(idx_valid, bk0a);          // ML-KEM PWM: 한 packed word만 필요

wire [3:0] read_mask_mldsa_pwm =
    pack_we2(idx_valid, bk0a, bk1a);    // ML-DSA PWM: 두 SBU, 두 word

wire [3:0] core_read_mask =
    is_mlkem_pwm ? read_mask_mlkem_pwm :
    is_mldsa_pwm ? read_mask_mldsa_pwm :
                   read_mask_fft;

wire [3:0] core_mu_read_en =
    (idx_valid && (!ctl_mem_down || core_reads_both_sides)) ? core_read_mask : 4'b0;

wire [3:0] core_md_read_en =
    (idx_valid && ( ctl_mem_down || core_reads_both_sides)) ? core_read_mask : 4'b0;
```

이건 특히 `mlkem_pwm` peak 63을 겨냥한 실험으로 봐야 합니다. Stage 4b에서도 `mlkem_pwm`이 103~105로 남아 있으므로, 이쪽은 SBU 내부보다 **BRAM read path + PWM active arithmetic** 둘 다 봐야 합니다.

### C. ML-DSA PWM에서 `a_i`가 functionally unused인데 secret을 태움

`rtl/phoenix/phoenix_top.v:414-419`:

```verilog
wire [DATA_W-1:0] sbu0_a = is_mlkem_pwm ? pwm0_a :
                            is_mldsa_pwm ? mu0a  : side0a;
wire [DATA_W-1:0] sbu0_b = is_mlkem_pwm ? pwm0_b :
                            is_mldsa_pwm ? md0a  : side0b;
wire [DATA_W-1:0] sbu1_a = is_mldsa_pwm ? mu1a : side1a;
wire [DATA_W-1:0] sbu1_b = is_mldsa_pwm ? md1a : side1b;
```

그런데 `rtl/phoenix/phoenix_top.v:502-507`에서 ML-DSA PWM의 실제 multiplicand는 `c_i=mu*a`, `b_i=md*a`입니다.

```verilog
wire [DATA_W-1:0] sbu0_c = is_mlkem_pwm ? cm_pwm :
                            is_mldsa_pwm ? mu0a : cm_q0;
wire [DATA_W-1:0] sbu1_c = is_mlkem_pwm ? cm_pwm :
                            is_mldsa_pwm ? mu1a : cm_q1;
```

그리고 `superbutterfly_sbu_routed.v`의 ML-DSA PWM은 `mA=c1`, `mB=b1`을 COMP3에 넣고, output도 `p6`만 씁니다. 즉 ML-DSA PWM에서 `a_i`는 기능적으로 필요 없습니다. 하지만 현재는 `a_i=mu0a/mu1a`로 들어가서 `a1/a2/a6` delay register chain을 계속 토글합니다.

이건 명백한 unused datapath leakage 후보입니다.

우선순위 3번 패치입니다.

```verilog
wire [DATA_W-1:0] sbu0_a =
    is_mlkem_pwm  ? pwm0_a :
    is_mldsa_pwm  ? 32'b0  :
                    side0a;

wire [DATA_W-1:0] sbu1_a =
    is_mldsa_pwm  ? 32'b0  :
                    side1a;
```

또는 SBU 내부에서 `SBU_MLDSA_PWM`일 때 `a1/a2/dA/a6` 자체를 zero-retime하는 방식도 가능합니다. 다만 top-level에서 먼저 0으로 주는 편이 영향 범위와 실험 해석이 더 깔끔합니다.

### D. blanking control의 “flopped control” 원칙

`superbutterfly_sbu_routed.v:43-44`:

```verilog
wire use_prd_candidate = `SBU_OPMODE(sel_i);
wire use_prd_blank = USE_PRD_INVALID_BLANKING && !valid_i && use_prd_candidate;
```

여기서는 invalid-cycle PRD 여부가 raw `sel_i`에서 바로 나옵니다. 현재 controller가 안정적으로 `sel_i`를 유지한다면 기능 문제는 없겠지만, OpenTitan 문서가 강조하는 것은 blanking control이 decode glitch에 취약하지 않도록 flop에서 직접 나와야 한다는 점입니다. ([OpenTitan][2])

이건 당장 최고 누출점은 아닐 수 있지만, 보안 RTL 스타일로는 다음처럼 바꾸는 게 낫습니다.

* `sel_i`, `valid_i`, `opmode_i`를 predecode flop에 먼저 저장
* blanking enable은 그 flop 값에서 생성
* full decode와 predecode가 불일치하면 assertion 또는 fatal 상태

### E. `mldsa_karatsuba24.v`는 bit 23을 버린다

`rtl/mul/mldsa_karatsuba24.v:17-20`:

```verilog
wire [11:0] a0 = a_i[11:0];
wire [10:0] a1 = a_i[22:12];
```

이건 “ML-DSA residue가 항상 `< q = 0x7fe001`, 즉 23-bit 안에 있음”이라는 전제에서는 맞습니다. 현재 normalize된 Montgomery residue만 흐른다면 기능적으로 괜찮습니다. 하지만 이 전제가 깨지면 bit 23이 조용히 버려집니다.

패치라기보다 assertion을 넣는 게 맞습니다.

```verilog
// simulation/formal
assert property (@(posedge clk) disable iff (!rst_n)
    mldsa_mode_valid |-> (a_i[23] == 1'b0 && b_i[23] == 1'b0));
```

또는 COMP3 입력에서 ML-DSA operand를 명시적으로 normalize/zero-extend해야 합니다.

### F. `tb_barrett_reduce`가 checks=0인 것은 테스트 공백

`tb/README.md`에 `tb_barrett_reduce`가 inconclusive라고 되어 있습니다. 이건 TVLA와 별개로 반드시 고쳐야 합니다. ML-KEM PWM/NTT의 active leakage를 줄이다 보면 reducer 구조를 건드릴 수 있는데, 이때 reducer TB가 vacuous이면 위험합니다.

## 4. 후속 실험 계획

### Phase 0 — 측정 방법을 먼저 고정

목표는 “RTL 패치 효과”와 “측정/순서/상태 artifact”를 분리하는 것입니다.

실험 기본값은 다음으로 고정하는 게 좋습니다.

```sh
TRACES=1000
SECRET_DIST=auto
TRACE_ORDER=shuffle
ORDER_SEED=<fixed per campaign>
OPS='mlkem_ntt mlkem_intt mlkem_pwm mldsa_ntt mldsa_intt mldsa_pwm'
```

그리고 각 bitstream마다 최소 세 가지 control을 같이 돌립니다.

| Control                   | 목적                                         |
| ------------------------- | ------------------------------------------ |
| fixed-vs-fixed            | 장비 drift / capture-order false positive 확인 |
| random-vs-random          | 분포 차이 없는 경우의 t-value baseline              |
| fixed-vs-random, shuffled | 실제 leakage assessment                      |

또한 결과는 `max |t|`만 보지 말고 아래를 자동 기록해야 합니다.

* peak index
* top-10 peak index와 t-value
* peak가 repeat run에서 같은 sample/cycle에 재현되는지
* cycle count unique 값
* clipping 여부
* bitstream SHA / RTL commit / Vivado seed
* trace length에 따른 multiple-comparison 보정 threshold 또는 p-value

Stage 4b repeat처럼 peak가 `mldsa_intt` 123 근처, `mldsa_pwm` 109 근처에 안정적으로 재현되는지 자동 비교해야 합니다.

### Phase 1 — peak를 RTL cycle로 매핑

현재 문서의 peak index만으로는 “BRAM read인지, COMP3인지, COMP1/COMP4인지, writeback인지”가 불명확합니다. 다음을 해야 합니다.

1. trigger 기준으로 sample index → clock cycle 매핑
2. 각 operation에 대해 cycle annotation 생성

   * memory read issue
   * BRAM output register
   * SBU s1 latch
   * COMP3 active
   * COMP1/COMP4 active
   * output register
   * writeback
3. `top-k peaks`를 이 annotation에 붙이기
4. 같은 peak가 RTL patch 후 어디로 이동하는지 확인

이걸 해두면 “Stage 4b에서 `mldsa_intt` 123이 COMP3인지 COMP1인지”를 바로 알 수 있습니다.

병행해서 Verilator/VCD 또는 Vivado SAIF로 fixed/random 입력에 대한 toggle difference를 뽑아야 합니다. 특히 다음 net group을 봐야 합니다.

* `u_comp3.u_kem_*`
* `u_comp3.u_dsa_*`
* `a1/a2/a6`, `b1/b2/b6`, `c1/c2/c6`
* `mu_a_dout`, `md_a_dout`
* `core_mu_read_en`, `core_md_read_en`
* `comp1_y`, `comp4_y`
* writeback `mu_b_din_w`, `md_b_din_w`

### Phase 2 — low-risk RTL ablation 순서

#### 2.1 Exact BRAM read enable

가장 먼저 할 패치는 pointwise/PWM exact bank read enable입니다.

예상 효과:

| Operation   | 기대                           |
| ----------- | ---------------------------- |
| `mlkem_pwm` | 가장 직접적인 개선 후보                |
| `mldsa_pwm` | 개선 후보                        |
| `ntt/intt`  | 모든 bank를 실제로 쓰므로 큰 변화 없을 가능성 |

중요한 점은 이 패치가 기능적으로는 거의 영향이 없어야 한다는 것입니다. 다만 BRAM output switching이 줄면서 power shape가 바뀔 수 있으므로, baseline/Stage 4b와 같은 seed로 비교해야 합니다.

---

#### 2.2 ML-DSA PWM `a_i=0`

다음은 ML-DSA PWM unused `a_i` blanking입니다.

예상 효과:

| Operation        | 기대        |
| ---------------- | --------- |
| `mldsa_pwm`      | 직접 개선 후보  |
| `mldsa_ntt/intt` | 영향 없어야 정상 |
| `mlkem_*`        | 영향 없어야 정상 |

이 패치는 작고 해석이 명확합니다. 만약 `mldsa_pwm`이 큰 폭으로 떨어지면, 지금까지 Stage 4b에 남아 있던 ML-DSA PWM 누출의 일부가 단순한 unused delay path였다는 뜻입니다.

---

#### 2.3 COMP3 internal algorithm-cone blanking

그다음은 COMP3 내부의 KEM/DSA cone 분리입니다.

예상 효과:

| Operation    | 기대                                                                         |
| ------------ | -------------------------------------------------------------------------- |
| `mldsa_ntt`  | 개선 가능                                                                      |
| `mldsa_intt` | 개선 가능, 현재 worst라 중요                                                        |
| `mldsa_pwm`  | 개선 가능                                                                      |
| `mlkem_*`    | DSA cone이 꺼져 power shape가 바뀜. 좋아질 수도, masking noise가 사라져 t가 일시적으로 커질 수도 있음 |

이 실험은 “OpenTitan blanking을 제대로 구현했다”는 관점에서 필수입니다. 다만 기존 unused cone switching이 우연히 noise처럼 동작했을 가능성이 있으므로, 단일 run 결과만 보고 판단하면 안 됩니다.

---

#### 2.4 Flopped blanking control

이건 보안 스타일과 glitch hardening을 위한 실험입니다.

* `sel_i` raw decode 기반 PRD enable 제거
* s1/predecode flop 기반 blanking enable 사용
* full decode와 predecode mismatch assertion 추가

기대 효과는 TVLA 수치 개선보다 구조적 안전성입니다. 그래도 placement가 바뀌므로 Stage 4b와 비교 측정은 필요합니다.

---

#### 2.5 조합 실험 매트릭스

아래 순서로 branch를 나누는 게 좋습니다.

| Branch | Patch                             |
| ------ | --------------------------------- |
| B0     | Stage 4b 그대로                      |
| B1     | B0 + exact BRAM read enable       |
| B2     | B1 + ML-DSA PWM `a_i=0`           |

각 branch마다 1000/1000 full six-op run을 먼저 돌리고, 효과가 큰 branch만 5000/5000으로 확대합니다.

## 5. blanking 이후의 현실적인 countermeasure 방향

여기서 중요한 결론은, **blanking은 unused path와 stale-state 누출을 줄이는 기법이지 active modular multiplication의 first-order leakage를 없애는 기법이 아니다**라는 점입니다.

PQC NTT hardware 쪽에서는 완전 masking이 비싸기 때문에 partial masking과 shuffling이 현실적인 절충안으로 자주 등장합니다. 최근 분석에서도 ML-KEM/ML-DSA의 NTT가 핵심 연산이고, full NTT masking은 register, randomness, share-separated datapath 때문에 area overhead가 크며, partial masking은 보통 first INTT layer와 pointwise multiplication을 보호하고 나머지는 shuffling 등에 의존하는 절충으로 설명됩니다. ([arXiv][6])

또 Kyber hardware에서는 Fisher–Yates 기반 compact shuffling architecture를 적용해 FPGA에서 CPA/TVLA로 평가한 사례가 있습니다. ([arXiv][7]) ML-DSA 쪽은 공격 연구에 비해 constructive countermeasure 연구가 아직 적다는 NIST PQC 2025 발표의 정리도 있습니다.

따라서 다음 장기 방향은 세 갈래입니다.

### 방향 1 — shuffling 먼저

비용 대비 가장 먼저 해볼 만합니다.

적용 후보:

* ML-DSA PWM coefficient order shuffle
* ML-KEM PWM packed word order shuffle
* NTT/INTT layer 내 conflict-free butterfly group shuffle
* 두 SBU에 들어가는 pair assignment shuffle

주의점:

* 단순 random-start index는 permutation entropy가 낮습니다.
* full Fisher–Yates가 어렵다면 group-level shuffle이라도 해야 합니다.
* TVLA에서는 shuffling이 peak를 퍼뜨려 `max |t|`를 낮출 수 있지만, 공격 가능성이 사라졌다는 뜻은 아니므로 CPA/template도 같이 해야 합니다.

### 방향 2 — partial masking

가장 현실적인 보호 대상은 다음입니다.

1. pointwise multiplication
2. first INTT layer
3. 현재 Stage 4b worst인 `mldsa_intt` peak cycle
4. `mlkem_pwm` peak 63 cycle

특히 pointwise는 secret×secret multiplication이라 leakage가 강합니다. NTT/INTT의 twiddle은 public이지만 operand는 secret이므로 multiplier/reducer는 계속 민감합니다.

Partial masking 실험은 이렇게 시작하는 게 좋습니다.

* memory에 two-share representation 저장
* linear add/sub는 share-wise 처리
* multiplication은 masked gadget 사용
* share recombination은 writeback 직전까지 금지
* DOM 스타일이면 glitch propagation을 막기 위해 share-separated registers와 fresh randomness 필요

### 방향 3 — full first-order masking

TVLA pass를 진짜 목표로 한다면 결국 이쪽입니다.

단, 비용이 큽니다.

* BRAM 두 배 또는 share bank 분리
* SBU 두 배 또는 share-aware SBU
* masked modular multiplication/reduction
* randomness bandwidth
* formal masking verification 또는 최소한 gate-level leakage sanity check

OpenTitan AES GHASH가 formal masking verification까지 언급하는 이유도 이 지점입니다. active masked datapath는 단순 RTL 기능 테스트만으로 안전성을 주장하기 어렵습니다. ([OpenTitan][5])

## 6. 내가 추천하는 즉시 실행 순서

가장 효율적인 순서는 이겁니다.

1. **Stage 4b 유지한 채 exact BRAM read enable 패치**

   * 기대 타깃: `mlkem_pwm`, `mldsa_pwm`
   * 이유: 현재 `4'hf` read enable은 unused bank `mem[0]` 누출 가능성이 큼

2. **ML-DSA PWM `a_i=0` 패치**

   * 기대 타깃: `mldsa_pwm`
   * 이유: 기능적으로 unused인 secret operand가 delay chain을 탐

3. **COMP3 내부 KEM/DSA cone blanking**

   * 기대 타깃: 전 operation
   * 이유: 현재 두 algorithm multiplier cone이 동시에 secret을 봄

4. **peak-to-cycle mapping + VCD/SAIF toggle correlation**

   * 이유: `mldsa_intt` worst peak가 어느 cone인지 식별해야 다음 패치가 정확해짐

5. **위 세 패치 후에도 `max |t| > 20`이면 blanking-only 중단**

   * 그때부터는 shuffling/partial masking으로 넘어가야 함

6. **partial masking은 pointwise와 first INTT layer부터**

   * 이유: 문헌적으로도 비용 대비 보호 대상으로 자주 선택되는 영역이고, 현재 결과에서도 PWM/INTT가 핵심 누출입니다. ([arXiv][6])

## 7. 최종 판단

이 프로젝트는 “HQC 제거 → ML-DSA 추가 → PHOENIX SBU 재사용”이라는 기능 리팩터는 상당히 잘 정리되어 있습니다. schedule, constants, instruction decode, basic diagnostics도 맞습니다.

하지만 SCA 관점에서는 아직 OpenTitan식 blanking이 **부분 적용** 상태입니다. 특히 다음 두 개는 반드시 고쳐야 합니다.

* `comp3_agile_modmul.v`에서 unused algorithm cone이 계속 토글되는 것
* `phoenix_top.v`에서 PWM/pointwise read enable이 모든 bank를 켜는 것

그 다음에도 남는 누출은 active multiplier/reducer leakage일 가능성이 높습니다. 따라서 목표가 “논문/대회 제출 수준으로 설득력 있는 TVLA 개선”이면 Stage 4b에서 위 blanking 완성 패치를 하고, 목표가 “진짜 TVLA pass”이면 shuffling과 partial masking까지 계획에 포함해야 합니다.
